# 外观与布局

## 三套外观

| id | 名称 | 配色 | 字体 / 留白 | 封面与播放器 | 默认展示 |
| --- | --- | --- | --- | --- | --- |
| `cloud` | 清爽云音乐 | 白 `#f5f6f8` / 浅灰 / 红 `#e02f2f` | 系统无衬线，紧凑（`--sp7:40px`） | **方形封面**（6px 圆角），白色常驻条 + 红色圆形播放键 | 列表 + 封面舞台 |
| `forest` | 森林音乐小屋 | 暖纸 `#f6efe0` / 森林绿 `#2f6b46` / 琥珀 `#c1832b` | **衬线标题**（Georgia / 宋体），最宽松（`--sp7:56px`） | 14px 圆角插画封面、纸张纤维纹理、**复古唱片**、琥珀歌词高亮 | 封面墙 + 唱片舞台 |
| `midnight` | 午夜黑胶 | 深蓝紫 `#0a0918` / 紫 `#9d8cff` / 青 `#57d2e8` | Avenir / Futura，中等（`--sp7:48px`） | **全站圆形黑胶 + 中心孔**、夜景星点、沉浸式发光歌词 | 封面墙 + 全屏歌词 |

三套都完整覆盖：页面、头部导航、曲库、单曲页、专辑 / 歌单、手记、
迷你播放器、全屏播放页、队列面板、分享弹层、外观面板、空状态、
`loading / buffering / blocked / error` 四种异常态。

所有颜色都走 CSS 变量，基础层里**没有任何硬编码深色表面**（有单元测试守着）。

### midnight 的手机性能

- `--blur: 0px`，`.head` / `.pl__bar` 的 `backdrop-filter` 直接关掉
- 当前曲封面的持续旋转动画关闭
- 星点背景降低不透明度

窄屏（`max-width:760px`）与**手动选手机布局**两种情况都生效。

## 默认与记忆

- **首次访问一律 `cloud`**。首帧脚本**完全不读** `prefers-color-scheme`，
  系统深色偏好不会覆盖默认值（有单元测试 + 真实浏览器测试双重把关）。
- 用户主动选择写入 `localStorage`：`zx.music.theme`、`zx.music.layout`。
- 无记录 / 值非法 / 存储不可用（隐私模式、配额耗尽、被策略禁用）→ 回退 `cloud` + `auto`，
  站点照常可用，只是不持久化。
- 旧版本存过的 `light` / `dark` 自动迁移为 `cloud` / `midnight`。

## 布局三档

| id | 行为 |
| --- | --- |
| `auto` | 按屏幕宽度：≤760px 手机形态，≤1000px 平板收敛，更宽为桌面 |
| `desktop` | 强制桌面结构。窄屏下导航横向滚动、播放器控件分行摆放，**不横向溢出** |
| `mobile` | 强制手机形态，**宽屏上也一样**，便于对照验证 |

布局与外观**互相独立**，切换其中一个不影响另一个。

### 为什么要构建期合成 CSS

同一份手机规则要同时满足「auto 时按宽度生效」和「手动选手机时无条件生效」。
手写两遍必然走样，所以 `assets/css/layout-{tablet,mobile,narrow,desktop}.css` 是**源文件**，
`tools/lib/css.mjs` 在构建期给它们加上不同作用域，产出 `dist/assets/css/layout.css`：

```css
@media (max-width:760px) { html[data-layout="auto"] .pl__bar { … } }
html[data-layout="mobile"] .pl__bar { … }
@media (max-width:900px) { html[data-layout="desktop"] .pl__bar { … } }
```

源文件不会进产物，避免有人误引用未加作用域的原始规则。

## 切换时保留什么

外观与布局切换**只改 `<html>` 上的 `data-theme` / `data-layout`**，
不重建任何 DOM、不碰 `<audio>`。因此下列全部原样保留：

播放 / 暂停状态、`currentTime`、队列与队列项 id、播放模式、随机洗牌袋与播放历史、
音量与静音、收藏、歌词行与高亮位置、当前曲目与音源 URL。

**暂停时切换仍是暂停，进度不会归零。** 站内导航同理。
这些都有 jsdom 与真实浏览器两层测试（3 主题 × 3 布局 × 播放/暂停两态）。

## 一个真实踩过的坑

`.pl` 上原本有 `backdrop-filter`。**`backdrop-filter` 会让元素成为 `position:fixed`
子元素的包含块**，于是 `inset:0` 的全屏播放页被压进那条 68px 的横条里，
控制按钮跑到视口外（y≈1009 / 视口 844），点都点不到。

修法：毛玻璃只加在 `.pl__bar` 上，`.pl` 保持纯净。
同理手机导航改用 `position:absolute`（相对 sticky 的 `.head`）。
两条都有 CSS 单元测试 + 真实浏览器的「全屏播放页按钮可见可点」断言守着。

## 入口在哪

- 桌面：头部「◐ 外观」按钮（带当前外观名）
- 手机：头部「◐」图标按钮，以及汉堡菜单里的「外观与布局」
- 全屏播放页右上角也有「◐」

面板里可选三套外观（带色板与说明）、三档布局，以及「恢复默认」。
